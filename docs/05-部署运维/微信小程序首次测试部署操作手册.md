# 微信小程序首次测试部署操作手册

> 适用工程：`workOrder-app-ui`、`workOrder-service`  
> 目标平台：微信小程序 `mp-weixin`  
> 适用场景：第一次部署、开发者工具联调、体验版真机测试  
> 当前功能范围：M1-B01～M1-D03、F01～F05，覆盖工单主流程、分支流程、SLA、站内消息、账户帮助、PC 运营功能和生产参数基线

完整的数据库、后端、PC、小程序、状态闭环、权限、并发和异常回归用例，请按 [G01 全链路联调与第一轮回归测试清单](../04-项目计划/G01-全链路联调与第一轮回归测试清单.md) 执行并留存证据。

## 1. 部署结论

首次部署按以下顺序执行：

1. 在本机启动 MySQL、Redis 和后端服务。
2. 使用 HBuilderX 将小程序运行到微信开发者工具，连接 `http://127.0.0.1:8080` 完成模拟器验证。
3. 准备带有效 HTTPS 证书的测试 API 域名，将后端部署到测试服务器。
4. 在微信公众平台登记 `request`、`uploadFile`、`downloadFile` 合法域名。
5. 使用测试域名重新发行 `mp-weixin`，在微信开发者工具上传代码。
6. 将开发版本设为体验版，在 iOS 和 Android 真机执行验收清单。

本机地址只能用于开发者工具模拟器。体验版和正式版不得使用 `localhost`、`127.0.0.1`、局域网 IP 或 HTTP 地址。

## 2. 当前交付边界

当前可以测试：

- 三角色账号、密码和图形验证码登录。
- 报修、派单、改派、接单、到场、评估、处理、完工、确认和评价闭环。
- 撤销、取消、退回、延期审批、SLA 预警、超期和自动关闭分支。
- 工单列表、详情、分类、附件、时间线、人员状态和权限隔离。
- 站内消息生成、未读/已读、失败退避和人工重试。
- 移动端账户资料、头像、密码、设置、帮助、关于和异常状态。
- PC 驾驶舱、维修绩效、分类、SLA、消息模板、发送记录和短信账户配置页面。

当前不要作为验收目标：

- 真实短信供应商发送和模板报备。
- 微信手机号登录、OpenID 绑定、微信支付和订阅消息。
- 未配置 HTTPS 测试域名时的体验版真机联网。
- 生产数据库迁移和生产发布。

## 5. 第一步：启动本地基础设施

以下两种方式二选一。第一次部署建议选择自己更熟悉的方式。

### 5.1 使用已安装的 MySQL 和 Redis

#### 5.1.1 创建数据库和账号

在 MySQL 客户端执行：

```sql
CREATE DATABASE IF NOT EXISTS workorder
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

CREATE USER IF NOT EXISTS 'workorder'@'%'
  IDENTIFIED BY '<仅用于本地测试的数据库密码>';

GRANT ALL PRIVILEGES ON workorder.* TO 'workorder'@'%';
FLUSH PRIVILEGES;
```

`'%'` 仅用于隔离的本地开发环境。测试服务器和生产环境必须限制数据库账号来源地址。

#### 5.1.2 导入完整初始化 SQL

进入 MySQL 命令行：

```powershell
mysql.exe -h 127.0.0.1 -P 3306 -u root -p
```

执行以下一个入口即可，路径使用正斜杠。该文件会创建并切换到 `workorder` 数据库，并完整导入当前全部模块：

```sql
SOURCE D:/person/workspace/workOrder-ui/workOrder-service/sql/00_workorder_full_init.sql;
```

该总文件包含删除并重建基础系统表的语句，只能导入全新或允许清空的本地、联调、回归数据库。不得导入生产存量数据库。

执行后检查：

```sql
SELECT COUNT(*) AS category_count FROM wo_category;
SELECT COUNT(*) AS role_count
FROM sys_role
WHERE role_key IN ('workorder_reporter', 'workorder_engineer', 'workorder_dispatcher');
SELECT COUNT(*) AS integration_user_count
FROM sys_user
WHERE user_name IN ('wo_reporter', 'wo_engineer', 'wo_dispatcher')
  AND del_flag = '0';
SELECT COUNT(*) AS notification_template_count
FROM wo_notification_template
WHERE enabled = 1 AND deleted = 0;
SELECT COUNT(*) AS workorder_job_count
FROM sys_job
WHERE job_group = 'WORKORDER';
SHOW TABLES LIKE 'wo_order';
SHOW TABLES LIKE 'wo_attachment';
```

预期：分类不少于 3 条、工单角色为 3 条、联调账号为 3 条、通知模板与工单定时任务均不为空，两张核心表均存在。

#### 5.1.3 启动 Redis

确认 Redis 可用：

```powershell
redis-cli.exe -h 127.0.0.1 -p 6379 ping
```

预期返回：

```text
PONG
```

### 5.2 使用 Docker Desktop

在 `workOrder-service` 目录执行：

```powershell
cd D:\person\workspace\workOrder-ui\workOrder-service
docker compose up -d mysql redis
docker compose ps
```

Docker 中的 MySQL 默认配置：

```text
数据库：workorder
账号：root
密码：password
端口：3306
```

SQL 初始化脚本只会在 MySQL 数据卷第一次创建时自动执行。已有数据卷不会自动重新执行新增脚本；此时应手工执行缺失的迁移脚本，不要为了重跑脚本直接删除数据卷。

## 6. 第二步：构建并启动本地后端

### 6.1 显式设置环境变量

当前配置文件的数据库和 Redis 默认值不完全一致。为避免连接到错误的数据库或 Redis，第一次启动必须显式设置：

```powershell
cd D:\person\workspace\workOrder-ui\workOrder-service

$env:SPRING_PROFILES_ACTIVE = 'local'
$env:DB_URL = 'jdbc:mysql://127.0.0.1:3306/workorder?useUnicode=true&characterEncoding=utf8&zeroDateTimeBehavior=convertToNull&useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai'
$env:DB_USERNAME = 'workorder'
$env:DB_PASSWORD = '<本地数据库密码>'
$env:REDIS_HOST = '127.0.0.1'
$env:REDIS_PORT = '6379'
$env:REDIS_PASSWORD = ''
$env:TOKEN_SECRET = '<至少32位的本地测试随机字符串>'
$env:WORKORDER_UPLOAD_PATH = 'D:/workOrder/uploadPath'
```

如果使用 Docker MySQL，将数据库账号改为 `root`，密码改为 `password`。

### 6.2 构建

```powershell
.\bin\build-local.ps1
```

成功后应生成：

```text
workOrder-service/ruoyi-admin/target/ruoyi-admin.jar
```

### 6.3 启动

保持同一个 PowerShell 窗口，执行：

```powershell
.\bin\run-local.ps1
```

看到 Spring Boot 启动完成日志且没有数据库、Redis 或 Mapper 异常后，再进行接口检查。

### 6.4 接口检查

另开一个 PowerShell 窗口：

```powershell
$captcha = Invoke-RestMethod -Method Get -Uri 'http://127.0.0.1:8080/captchaImage'
$captcha.code
$captcha.captchaEnabled
```

预期 `code` 为 `200`。如请求失败，先不要启动小程序，按第 13 章排查后端。

### 6.5 初始登录账号

完整初始化 SQL 提供以下本地联调账号：

| 账号 | 初始密码 | 用途 |
|---|---|---|
| `admin` | `admin123` | 首次管理和故障排查 |
| `wo_reporter` | `admin123` | 报修、撤销、确认、评价 |
| `wo_engineer` | `admin123` | 接单、到场、处理、完工 |
| `wo_dispatcher` | `admin123` | 分派、改派、审批和运营配置 |

以上账号只用于本地和隔离测试环境。首次联调成功后立即修改密码；生产环境不得保留这些账号或初始密码。

## 7. 第三步：在微信开发者工具连接本机后端

### 7.1 配置本次构建的接口地址

完全退出已经运行的 HBuilderX，再从设置过环境变量的 PowerShell 启动 HBuilderX。示例：

```powershell
$env:VUE_APP_BASE_API = 'http://127.0.0.1:8080'
$env:VUE_APP_PRIVACY_URL = ''
$env:VUE_APP_SERVICE_AGREEMENT_URL = ''
Start-Process -FilePath '<HBuilderX.exe 的实际路径>'
```

环境变量只对从该 PowerShell 启动的 HBuilderX 生效。不要在 HBuilderX 已经运行时修改变量后直接构建。

### 7.2 首次配置 HBuilderX

1. 使用 HBuilderX 打开 `D:\person\workspace\workOrder-ui\workOrder-app-ui`。
2. 打开 `manifest.json`，确认微信小程序 AppID 正确。
3. 选择“运行 → 运行到小程序模拟器 → 微信开发者工具”。
4. 第一次运行时，根据提示配置微信开发者工具安装路径。
5. 如果 HBuilderX 无法拉起微信开发者工具，在微信开发者工具“设置 → 安全设置”中开启服务端口。

开发构建目录通常为：

```text
workOrder-app-ui/unpackage/dist/dev/mp-weixin
```

如果 HBuilderX 未自动导入，在微信开发者工具中手工导入该目录。

### 7.3 本地模拟器设置

仅在本机模拟器联调阶段，在微信开发者工具“详情 → 本地设置”中勾选“不校验合法域名、web-view、TLS 版本以及 HTTPS 证书”。

此设置只用于连接 `http://127.0.0.1:8080`。生成体验版前必须取消勾选，并使用合法 HTTPS 域名重新验证。

### 7.4 确认接口地址已进入构建产物

构建完成后，在项目根目录执行：

```powershell
rg -n "127.0.0.1:8080" workOrder-app-ui\unpackage\dist\dev\mp-weixin
```

能够找到本次地址，说明环境变量已进入构建产物。找不到时，完全退出 HBuilderX、重新从设置环境变量的 PowerShell 启动，并重新编译。

### 7.5 本机冒烟测试

按以下顺序验证：

1. 登录页可以加载图形验证码。
2. 使用测试账号登录，进入首页。
3. 打开报修页面，分类可以正常加载。
4. 填写位置、紧急程度、影响范围和故障描述。
5. 先不上传附件，提交一张工单。
6. 跳转详情后核对工单号、状态、申请人和时间线。
7. 返回“我的工单”，确认新工单出现在列表中。
8. 再提交一张带小于 1 MB 图片的工单。
9. 在详情中点击图片，确认能够下载和预览。
10. 断开后端后重试一次，确认页面显示失败且保留已填写内容。

当前 Spring Boot 配置的单文件有效上限为 10 MB。第一次测试使用 1 MB 以内的 JPG 或 PNG，避免把大小限制问题与部署问题混在一起。

## 8. 第四步：准备体验版 HTTPS 测试环境

如果只进行开发者工具模拟器测试，可以暂时停在第 7 章。需要手机扫码测试或发布体验版时，必须继续执行本章。

### 8.1 测试域名要求

测试 API 地址应类似：

```text
https://api-test.example.com
```

必须满足：

- 使用受信任机构签发的有效 HTTPS 证书。
- 证书域名与测试 API 域名一致，证书链完整且未过期。
- 域名可以从公网访问，不使用 IP、`localhost` 或局域网地址。
- 外部只开放 443；MySQL、Redis 和后端 8080 不直接暴露到公网。
- 微信公众平台允许登记该域名。

### 8.2 构建后端 JAR

在开发机执行：

```powershell
cd D:\person\workspace\workOrder-ui\workOrder-service
.\bin\build-local.ps1
```

将以下文件上传到测试服务器：

```text
ruoyi-admin/target/ruoyi-admin.jar
sql/00_workorder_full_init.sql
```

`00_workorder_full_init.sql` 只用于全新或可清空的测试数据库。生产存量库必须使用经过审核的增量迁移，不得执行该完整初始化文件。

### 8.3 测试服务器环境变量

测试服务器使用 `prod` 配置，并通过环境变量注入真实值：

```text
SPRING_PROFILES_ACTIVE=prod
DB_URL=jdbc:mysql://127.0.0.1:3306/workorder?useUnicode=true&characterEncoding=utf8&zeroDateTimeBehavior=convertToNull&useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai
DB_USERNAME=workorder_app
DB_PASSWORD=<测试数据库强密码>
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_PASSWORD=<测试Redis密码>
TOKEN_SECRET=<至少32位随机密钥>
WORKORDER_UPLOAD_PATH=/data/workorder/upload
SWAGGER_ENABLED=false
```

要求：

- 数据库账号只授权 `workorder` 数据库。
- Redis 设置密码并限制来源地址。
- `TOKEN_SECRET` 不使用仓库默认值，且不提交到代码仓库。
- `/data/workorder/upload` 由后端运行账号读写，不由 Nginx 直接公开。

### 8.4 Linux systemd 示例

服务文件 `/etc/systemd/system/workorder.service`：

```ini
[Unit]
Description=Hospital WorkOrder Service
After=network.target mysql.service redis.service

[Service]
User=workorder
Group=workorder
WorkingDirectory=/opt/workorder
EnvironmentFile=/etc/workorder/workorder.env
ExecStart=/usr/bin/java -jar /opt/workorder/ruoyi-admin.jar
SuccessExitStatus=143
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

加载并启动：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now workorder
sudo systemctl status workorder
sudo journalctl -u workorder -n 200 --no-pager
```

### 8.5 Nginx HTTPS 示例

```nginx
server {
    listen 443 ssl http2;
    server_name api-test.example.com;

    ssl_certificate     /etc/nginx/cert/fullchain.pem;
    ssl_certificate_key /etc/nginx/cert/private.key;

    client_max_body_size 25m;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        proxy_connect_timeout 10s;
        proxy_read_timeout 60s;
        proxy_send_timeout 60s;
    }
}
```

检查并重载：

```bash
sudo nginx -t
sudo systemctl reload nginx
curl -fsS https://api-test.example.com/captchaImage
```

应返回包含 `code: 200` 的 JSON。若浏览器可访问但小程序失败，继续检查证书链和微信合法域名配置。

## 9. 第五步：配置微信公众平台

使用小程序管理员或有权限的成员登录微信公众平台。菜单名称可能随平台调整，通常位于“开发管理 → 开发设置”。

### 9.1 服务器域名

将同一个测试 API 域名分别登记为：

| 配置项 | 本项目用途 | 示例 |
|---|---|---|
| request 合法域名 | 登录、分类、工单接口 | `https://api-test.example.com` |
| uploadFile 合法域名 | 附件上传 | `https://api-test.example.com` |
| downloadFile 合法域名 | 附件预览和下载 | `https://api-test.example.com` |

只填写协议和域名，不填写接口路径。保存后等待平台配置生效，再在开发者工具中刷新项目配置。

### 9.2 业务域名

只有登录页中的隐私政策和用户服务协议使用 `web-view` 时，才需要配置对应业务域名。业务域名需要按微信平台要求放置校验文件。

内部功能测试可以暂时不配置协议 URL，此时点击协议会提示“尚未配置”；提交审核前必须提供正式内容和可访问地址。

### 9.3 隐私保护指引

按当前代码实际使用的能力填写，不提前声明尚未使用的能力：

- 选择相册图片或拍照，用于上传报修附件。
- 上传的故障描述、位置文本、联系电话和现场图片仅用于处理工单。
- 当前版本未调用定位接口时，不声明精确位置权限；以后接入到场定位时再同步更新。

配置内容必须与体验版实际行为一致。新增相机、相册、定位或手机号能力时，应同时更新代码、平台隐私指引和测试用例。

## 10. 第六步：发行并上传微信体验版

### 10.1 使用 HTTPS 测试地址重新启动 HBuilderX

完全退出 HBuilderX，然后在 PowerShell 执行：

```powershell
$env:VUE_APP_BASE_API = 'https://api-test.example.com'
$env:VUE_APP_PRIVACY_URL = 'https://www.example.com/privacy'
$env:VUE_APP_SERVICE_AGREEMENT_URL = 'https://www.example.com/service-agreement'
Start-Process -FilePath '<HBuilderX.exe 的实际路径>'
```

如果协议页暂未准备好，内部体验版可以先留空，但必须在测试记录中标注。

### 10.2 HBuilderX 发行

1. 打开 `workOrder-app-ui`。
2. 再次确认 `manifest.json` 中的 AppID。
3. 选择“发行 → 小程序-微信”。
4. 输入本次小程序名称和 AppID。
5. 不勾选自动上传，第一次部署使用微信开发者工具手工上传，便于观察编译和域名问题。
6. 等待构建完成。

## 13. 常见故障排查

### 13.1 后端无法启动

检查顺序：

1. `java -version` 和 `mvn -version` 是否可执行。
2. 3306、6379、8080 是否被占用。
3. `DB_URL`、`DB_USERNAME`、`DB_PASSWORD` 是否为当前数据库实际值。
4. `REDIS_HOST` 是否显式设置为 `127.0.0.1`。
5. `00_workorder_full_init.sql` 是否执行完成，末尾汇总查询是否全部返回预期数量。
6. 日志中是否存在 `Access denied`、`Connection refused` 或 Mapper 加载错误。

### 13.2 验证码加载失败

- 直接访问 `/captchaImage` 判断是后端问题还是小程序问题。
- 检查 Redis 是否可用。
- 检查构建产物中的 API 地址是否正确。
- 本机模拟器检查是否已临时关闭域名校验。
- 真机检查 HTTPS 证书和 `request` 合法域名。

### 13.3 真机请求仍访问 localhost

原因是 HBuilderX 构建时没有读取新的 `VUE_APP_BASE_API`。完全退出 HBuilderX，从设置了 HTTPS 环境变量的 PowerShell 重新启动，重新发行并用 `rg` 检查产物。

### 13.4 提示“不在以下 request 合法域名列表中”

- 在微信公众平台分别配置 `request`、`uploadFile` 和 `downloadFile` 域名。
- 只填写 `https://域名`，不附加接口路径。
- 确认开发者工具使用的是正确 AppID。
- 刷新开发者工具项目配置，保持域名校验开启后重试。

### 13.5 分类为空

检查 `07_workorder_seed.sql` 是否执行：

```sql
SELECT category_id, category_code, category_name, status
FROM wo_category
WHERE del_flag = '0';
```

### 13.6 接口返回 403

- 管理员账号应拥有全部权限。
- 普通账号检查是否分配了对应工单角色。
- 检查 `05_workorder_menu.sql` 和 `06_workorder_role_grant.sql` 是否执行。
- 重新登录以刷新权限缓存。

### 13.7 附件上传出现 413

- Nginx `client_max_body_size` 建议设置为 `25m`。
- 当前 Spring Boot 单文件上限为 `10MB`，测试文件必须小于该值。
- 修改上传上限后应同时核对 Nginx、Spring Boot 和业务附件校验，不能只修改一处。

### 13.8 附件上传成功但无法预览

- 检查 `downloadFile` 合法域名。
- 检查下载请求是否携带 `Authorization`。
- 检查当前账号是否能查看附件所属工单。
- 检查后端私有附件目录是否存在且运行账号有读取权限。

### 13.9 HBuilderX 无法打开微信开发者工具

- 在 HBuilderX 运行设置中配置微信开发者工具安装目录。
- 在微信开发者工具“设置 → 安全设置”中开启服务端口。
- 仍失败时手动打开微信开发者工具，并导入 HBuilderX 控制台显示的 `mp-weixin` 目录。

## 14. 停止、更新和回退

### 14.1 停止本地后端

在运行后端的 PowerShell 窗口按 `Ctrl+C`。MySQL 和 Redis 根据本机安装方式停止。

Docker 基础设施停止：

```powershell
cd D:\person\workspace\workOrder-ui\workOrder-service
docker compose stop mysql redis
```

`stop` 不删除数据卷。不要使用带数据卷删除参数的命令，除非已经确认数据可以丢弃并完成备份。

### 14.2 更新体验版

1. 记录当前小程序、后端和数据库版本。
2. 备份数据库。
3. 执行新增的向前兼容 SQL。
4. 替换后端 JAR 并重启。
5. 用相同 HTTPS 域名重新发行小程序。
6. 上传递增版本号，设置为新的体验版。
7. 执行本手册第 11 章冒烟测试。

### 14.3 回退

- 保留上一版后端 JAR 和对应配置记录。
- 保留上一版小程序构建产物和上传版本号。
- 数据库脚本优先采用向前兼容策略；未编写并验证回退 SQL 时，不直接回滚表结构。
- 回退后重新执行登录、提交、列表、详情和附件测试。
