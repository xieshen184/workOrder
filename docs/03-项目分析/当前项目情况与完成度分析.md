# 当前项目情况与完成度分析

> 分析日期：2026-09-14  
> 依据：项目源码、`项目资料/页面构思-初版.txt`、会议纪要图片和 `项目资料/0.mp4` 演示视频。

## 1. 总体判断

项目已经具备完整的若依三端工程骨架和一批可演示的移动端业务页面，但尚未形成真实业务闭环。当前更接近“移动端视觉原型 + 若依通用底座”，不是可上线的工单系统。

按“页面、接口、数据、流程、运维”五个维度粗估：

| 维度 | 当前完成度 | 判断依据 |
|---|---:|---|
| 移动端业务页面 | 约 55% | 首页、提交、派单、处理、评价已有；我的工单、到场、评估、延期、完工确认、消息等缺失 |
| PC 管理端业务页面 | 约 10% | 若依框架完整，但工单、调度、SLA、统计、消息业务页未实现 |
| 后台业务接口 | 约 5% | 登录和系统管理底座存在；工单业务模块、Controller、Service、Mapper 基本不存在 |
| 数据库业务模型 | 0% | 未发现工单业务表和初始化脚本 |
| 真实流程闭环 | 约 5% | 页面操作主要使用本地 Mock、随机数和延时模拟 |
| 综合可上线完成度 | 约 15%–20% | 具备工程基础和视觉方向，但关键业务、数据、安全和运维仍需实施 |

完成度是基于代码可运行能力的工程估算，不等同于已写文件数量。

## 2. 各子项目现状

### 2.1 移动端 `workOrder-app-ui`

技术：UniApp、Vue 2、uView UI、uni-ui，正式交付目标为微信小程序 `mp-weixin`；保留若依移动端登录与个人中心框架。

已存在的业务页：

- 首页/看板：今日申报、今日完成、趋势图、快捷入口、状态统计。
- 工单提交：电话、故障说明、附件、提交按钮。
- 工单派发：待派/已派列表、派单详情和选择维修人员。
- 工单处理：待处理/执行中/已完成列表、处理详情和日志。
- 完工评价：待评价/已评价列表、评价表单和结果。

主要问题：

- 首页统计和趋势数据通过 `setTimeout`、随机数或静态数组生成。
- 提交页模拟上传和成功提示，上传地址包含示例域名。
- 派单、处理、评价的接口文件返回本地 Mock。
- 存在 `/repair/submit` 的前端定义，但页面未真正使用，后端也没有对应实现。
- 页面编码文件存在乱码风险，需要统一检查 UTF-8 保存和构建环境。

### 2.2 PC 端 `workOrder-ui`

技术：Vue 2、Element UI、若依 3.9.0。

系统管理、用户、角色、菜单、部门、字典和监控等通用页面存在；未发现工单业务菜单、页面、接口封装和状态管理。项目可以作为后台壳直接扩展，视觉上应继续复用若依布局和 Element UI 交互模式。

### 2.3 后台 `workOrder-service`

技术：Spring Boot 2.5.15、Java 8、MyBatis、MySQL、Redis、JWT、Quartz、Swagger，若依 3.9.0 多模块结构。

现有模块提供用户权限、系统配置、日志、定时任务等基础能力；未发现工单业务 Maven 模块、业务表、Controller、Service、Mapper 和状态机。README 也说明当前没有业务代码。

构建检查曾受工作区沙箱对既有 `target` 目录的写权限影响，不能据此判断源码编译失败；实施阶段应在正常开发环境重新执行完整 Maven 构建和测试。

## 3. 现有视觉情况

移动端演示形成了明确风格：

- 浅灰蓝背景、白色卡片、圆角和轻阴影。
- 首页使用绿色“申请”、蓝紫色“派发”、橙色“处理”三块高识别入口。
- 派单流程以紫色为主，处理流程以青绿色为主，评价流程以橙色为主。
- 工单卡片使用左侧状态色条，列表顶部使用分段标签，详情按基本信息/故障信息/附件/处理日志分卡片。
- 首页、工作台、我的使用三栏底部导航。

PC 端当前是标准若依风格：深色左侧栏、白色顶部栏、浅灰工作区、Element UI 表格/表单/弹窗。新增业务页面应复用，不另建一套视觉系统。

## 4. 重点风险

### P0：上线阻断

- 后端无工单业务实现，数据库无业务表，前后端无法形成真实闭环。
- 前端 Mock 容易在测试中制造“已完成”假象，必须逐页替换并删除。
- 状态、权限和数据归属若只由前端控制，将产生越权派单、代确认、重复完工等严重问题。

### P1：高风险

- 后端 Redis 默认地址指向固定内网 IP，环境切换会失败。
- JWT、数据库、短信和对象存储配置需清理默认值与明文密钥。
- 生产 Swagger、文件下载权限、日志敏感字段需要收紧。
- SLA 不能硬编码在页面或定时任务，应配置化并在工单创建时形成截止时间快照。
- 并发派单、接单和完工必须使用乐观锁和幂等键。

### P2：实施注意

- 页面编码乱码和中文资源应统一为 UTF-8。
- 附件要有临时态、绑定态、鉴权下载和过期清理。
- Quartz 多实例要避免重复扫描和重复短信。
- 若依菜单权限之外还需要工单所属人、当前处理人、部门数据范围校验。

## 5. 接手建议

1. 先落地数据库、工单深模块和状态机，再接页面，不从首页统计开始。
2. 按“报修—派单—接单—到场—处理—完工—确认—评价”打通一条最小真实链路。
3. 每接通一个页面即删除对应 Mock，并增加接口/行为测试。
4. 通知先做事务任务表和站内信，再开真实短信，避免业务事务绑定供应商稳定性。
5. 驾驶舱、绩效和运营配置在核心闭环稳定后实施。
