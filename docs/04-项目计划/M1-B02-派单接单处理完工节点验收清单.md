# M1-B02 派单、接单、到场、处理与完工节点验收清单

## 交付范围

本节点交付工单从“待派单”到“待确认”的完整处理链路，覆盖调度管理员、维修人员两类角色，以及 PC 管理端和微信小程序端。确认、退回和评价属于 M1-B03，不纳入本节点完成判定。

## 接口清单

| 方法 | 路径 | 权限 | 完成条件 |
|---|---|---|---|
| GET | `/workorder/admin/engineers` | `workorder:engineer:list` | 仅返回有效维修人员及其部门、值班状态、工作状态和当前负载 |
| POST | `/workorder/orders/{id}/assign` | `workorder:order:assign` | 待派单工单进入待接单，生成有效派单记录并写入审计日志 |
| POST | `/workorder/orders/{id}/reassign` | `workorder:order:reassign` | 结束原派单，生成新派单，工单回到待接单并更新当前处理人 |
| POST | `/workorder/orders/{id}/accept` | `workorder:order:accept` | 仅当前处理人可以接单，记录接单时间并更新派单记录 |
| POST | `/workorder/orders/{id}/arrive` | `workorder:order:arrive` | 仅当前处理人可以到场确认，写入到场记录并进入处理中 |
| POST | `/workorder/orders/{id}/assessment` | `workorder:order:assess` | 在处理中追加故障评估，不改变主状态 |
| POST | `/workorder/orders/{id}/progress` | `workorder:order:progress` | 在处理中追加过程记录，不改变主状态 |
| POST | `/workorder/orders/{id}/finish` | `workorder:order:finish` | 校验完工说明和附件，写入完工记录并进入待确认 |
| POST | `/workorder/attachments` | `workorder:attachment:upload` | 支持 `SUBMIT/ARRIVAL/PROCESS/FINISH` 阶段；不传阶段时兼容为 `SUBMIT` |

所有状态写接口必须携带 `Idempotency-Key`，请求体必须携带客户端最后一次读取到的 `version`。成功响应返回最新 `status`、`version` 和 `idempotentReplay`。

## 状态链路

| 当前状态 | 动作 | 目标状态 | 执行角色 |
|---|---|---|---|
| `WAIT_ASSIGN` | `ASSIGN` | `WAIT_ACCEPT` | 调度管理员 |
| `WAIT_ACCEPT` | `REASSIGN` | `WAIT_ACCEPT` | 调度管理员 |
| `WAIT_ACCEPT` | `ACCEPT` | `ACCEPTED` | 当前维修人员 |
| `ACCEPTED` | `REASSIGN` | `WAIT_ACCEPT` | 调度管理员 |
| `ACCEPTED` | `ARRIVE` | `PROCESSING` | 当前维修人员 |
| `PROCESSING` | `REASSIGN` | `WAIT_ACCEPT` | 调度管理员 |
| `PROCESSING` | `ASSESS` | `PROCESSING` | 当前维修人员 |
| `PROCESSING` | `PROGRESS` | `PROCESSING` | 当前维修人员 |
| `PROCESSING` | `FINISH` | `WAIT_CONFIRM` | 当前维修人员 |

## 数据一致性

- 状态更新必须同时匹配工单 ID、当前状态和版本号；成功后版本号递增。
- 状态冲突或旧版本请求不得覆盖新数据，客户端收到冲突后重新加载详情。
- 同一用户、同一动作和同一幂等键重复提交，只产生一次状态变化、一次过程记录和一条动作日志。
- 派单和改派从服务端读取维修人员身份快照，不接受客户端提交姓名或部门。
- 改派时原派单必须结束，新派单必须生效，不允许同时存在两条有效派单。
- 接单时同步更新当前派单记录的接单时间和状态。
- 到场、评估、进度和完工记录必须保存执行人、内容及业务发生时间。
- 过程附件只能绑定当前执行人上传、尚未绑定、阶段匹配且未删除的附件。
- 工单状态更新、派单或过程记录、附件绑定和动作日志必须位于同一数据库事务。
- 详情接口继续只返回受鉴权下载地址，不返回私有存储对象键。

## PC 管理端

- 工单列表使用真实分页接口，支持关键词、状态、分类和紧急程度筛选。
- 列表具备加载、空数据、失败重试和分页状态。
- 详情展示工单核心信息、当前处理人、附件和完整操作时间线。
- 仅当详情 `allowedActions` 包含 `ASSIGN` 或 `REASSIGN` 时显示对应按钮。
- 派单窗口从真实维修人员接口加载候选人，不使用静态人员数据。
- 提交期间禁止重复点击；提交失败保留已选人员和说明。
- 并发冲突时明确提示工单已变化，并自动重新加载最新详情和列表。

## 微信小程序

- 我的维修任务使用真实分页接口，不保留模拟工单和示例图片地址。
- 列表支持下拉刷新、加载更多、空状态和失败重试。
- 详情按钮完全由 `allowedActions` 控制，不根据本地状态自行推断权限。
- 接单操作需要二次确认，提交期间禁止重复点击。
- 到场、故障评估、处理进度和完工表单校验必填项，失败后保留填写内容和已上传附件。
- 需要零部件时必须填写零部件说明。
- 完工必须填写完工结果，并按产品要求上传完工证明。
- 每次用户发起的新操作生成新的幂等键；网络失败重试复用原幂等键。
- 并发冲突后重新加载详情，不继续使用旧版本提交。
- 页面保持现有色彩、卡片、间距和导航样式，不修改既有视觉风格。

## 验收场景

| 编号 | 检查项 | 通过标准 |
|---|---|---|
| B02-01 | 正常闭环 | 待派单工单依次完成派单、接单、到场、评估、进度和完工，最终状态为 `WAIT_CONFIRM` |
| B02-02 | 非法状态 | 在不允许的状态执行动作被拒绝，工单、记录、附件和日志均不发生变化 |
| B02-03 | 非当前处理人 | 非当前维修人员不能接单、到场、评估、更新进度或完工 |
| B02-04 | 幂等重试 | 同一动作使用相同幂等键重试返回同一结果，不产生重复业务记录 |
| B02-05 | 并发冲突 | 两个请求使用同一旧版本提交时最多一个成功，失败方重新加载最新版本 |
| B02-06 | 改派一致性 | 原派单正确结束，新处理人收到待接单任务，原处理人不能继续操作 |
| B02-07 | 附件归档 | 到场、处理和完工附件分别归档到正确阶段，越权或阶段不匹配时整次命令失败 |
| B02-08 | PC 派单 | 管理端可查询、查看详情、选择真实维修人员并完成派单和改派 |
| B02-09 | 小程序处理 | 维修人员可在微信小程序完成接单至完工主流程，失败重试不重复写入 |
| B02-10 | 审计可追溯 | 详情时间线完整显示每次动作的执行人、时间、前后状态和操作说明 |
