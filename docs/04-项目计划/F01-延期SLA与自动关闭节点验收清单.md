# F01 延期、SLA 与自动关闭节点验收清单

## 交付范围

本节点完成工单延期申请与审批、SLA 规则配置、SLA 预警与超期扫描、评价窗口到期自动关闭，并交付微信小程序延期申请页和 PC 延期审批、SLA 规则页面。本节点完成开发与自动化验证，不包含 MySQL 实库联调、微信开发者工具构建和三角色端到端验收。

## 延期申请闭环

### 微信小程序操作

- 处理中的工单仅在当前维修人员具有延期权限、当前 SLA 允许延期且不存在待审申请时显示“申请延期”。
- 延期页展示原完成截止时间、当前有效截止时间和剩余时长。
- 新截止时间必须晚于当前有效截止时间，延期原因必填且最多 500 字，可上传最多 10 张佐证图片。
- 提交后工单继续按原有效截止时间计时，只有审批通过后才切换为新截止时间。
- 待审申请禁止重复提交；被拒绝后保留上次填写内容供修改；已同意后如果工单仍处于处理中，可按最新截止时间再次申请。
- 页面重新进入或返回详情时重新读取服务端的待审标志、工单版本和允许动作，不依赖本地旧状态。

### PC 审批操作

- 调度管理员进入“延期审批”，可按待审、已同意、已拒绝、已取消和关键字筛选申请。
- 列表展示工单、申请人、原截止时间、申请截止时间、申请原因、状态和申请时间。
- 同意后写入工单 `extension_deadline`，清除待审标志并保留原 SLA 截止时间快照。
- 拒绝必须填写原因，只清除待审标志，不修改任何截止时间。
- 工单完工时仍有待审申请，系统在同一事务中将申请改为“已取消”，不留下永久待审记录。
- 工单改派时自动取消原处理人的待审申请；新处理人接单并进入处理后可重新申请。

### 并发与审计

- 同一工单在数据库层最多存在一条 `PENDING` 延期申请。
- 创建接口必须携带 `Idempotency-Key`；相同请求重试返回首次申请，不重复变更版本、绑定附件或写日志，同键用于不同内容时返回冲突。
- PC 延期列表复用若依部门数据范围，调度管理员只能查看授权部门内工单的申请。
- 创建申请同时校验当前处理人、工单状态、SLA 延期许可、工单版本和新截止时间。
- 审批与完工统一按“先锁工单、再处理延期记录”的顺序执行，避免并发审批和完工发生反向加锁。
- 申请、同意和拒绝分别记录 `REQUEST_DELAY`、`APPROVE_DELAY`、`REJECT_DELAY` 业务动作日志。
- 申请记录、工单待审标志、延期截止时间、附件绑定和动作日志位于同一事务中，任一步失败均整体回滚。

## SLA 规则管理

- 调度管理员进入“SLA 规则”，可按关键字、分类、紧急程度和状态筛选。
- 支持新增、编辑、启用和停用，不提供删除入口。
- 规则编码为 2 至 32 位大写字母、数字或下划线，创建后不可修改。
- 规则可配置分类、紧急程度、优先级、生效区间、响应时限、到场时限、完成时限、预警提前量和是否允许延期。
- 相同分类范围、紧急程度、优先级的启用规则不允许生效时间重叠；停用规则不占用有效期，重新启用时重新校验。
- 创建工单时快照规则编号、各阶段截止时间、预警提前量和延期许可。后续修改规则只影响新工单，不回写历史工单。

## SLA 扫描与自动关闭

| 工单状态 | 当前检查截止时间 | 超期结果 |
|---|---|---|
| `WAIT_ASSIGN`、`WAIT_ACCEPT` | 响应截止时间 | 响应超期 |
| `ACCEPTED` | 到场截止时间 | 到场超期 |
| `PROCESSING` | 延期截止时间；无延期时为完成截止时间 | 完成超期 |

- SLA 扫描任务每分钟执行一次，更新当前预警标志、总超期标志和三个阶段超期标志。
- 阶段超期标志一旦形成即保留，用于后续统计；预警标志随当前阶段和预警窗口动态变化。
- 首次进入预警或首次形成总超期时写入系统业务日志；任务重跑不重复写相同日志。
- 后台扫描不递增用户业务版本，避免维修人员正在填写的合法操作因定时扫描失效。
- 已确认完成且超过评价窗口仍未评价的工单，每天自动从 `COMPLETED` 关闭为 `CLOSED`。
- 评价窗口通过 `WORKORDER_AUTO_CLOSE_DAYS` 配置，默认 7 天。

## 接口

| 方法 | 地址 | 权限 | 作用 |
|---|---|---|---|
| POST | `/workorder/orders/{id}/delay-requests` | `workorder:delay:add` | 当前维修人员提交延期申请 |
| GET | `/workorder/orders/{id}/delay-requests/latest` | 延期申请、查询或列表权限 | 查询可见工单最新延期记录 |
| GET | `/workorder/admin/delay-requests` | `workorder:delay:list` | PC 分页查询延期申请 |
| POST | `/workorder/delay-requests/{id}/approve` | `workorder:delay:approve` | 同意延期申请 |
| POST | `/workorder/delay-requests/{id}/reject` | `workorder:delay:approve` | 拒绝延期申请 |
| GET | `/workorder/sla-rules` | `workorder:sla:list` | 分页查询 SLA 规则 |
| GET | `/workorder/sla-rules/{id}` | `workorder:sla:query` | 查询 SLA 规则详情 |
| POST | `/workorder/sla-rules` | `workorder:sla:add` | 新增 SLA 规则 |
| PUT | `/workorder/sla-rules/{id}` | `workorder:sla:edit` | 编辑、启用或停用 SLA 规则 |

## 数据库与任务

执行 `workOrder-service/sql/11_workorder_f01_sla_delay.sql` 后：

- 工单表增加预警提前量和延期许可快照字段，并按历史规则回填。
- 创建 `wo_delay_request`，使用生成列唯一索引保证同一工单最多一条待审申请。
- 创建延期审批和 SLA 规则菜单及按钮权限，并按角色最小授权。
- 创建每分钟 SLA 扫描任务和每天自动关闭任务，任务禁止并发执行。
- 脚本支持重复执行；Docker Compose 初始化链已包含 09、10、11 三个增量脚本。

## 验收场景

| 编号 | 检查项 | 通过标准 |
|---|---|---|
| F01-01 | 动作显示 | 只有符合状态、处理人、权限、SLA 许可且无待审申请时显示延期入口 |
| F01-02 | 申请校验 | 旧版本、非当前处理人、禁止延期、截止时间未延后、重复待审和幂等键误用均被拒绝 |
| F01-03 | 附件绑定 | 只绑定当前上传者未绑定的临时附件，部分不合法时整单回滚 |
| F01-04 | 同意延期 | 仅更新延期截止时间，原 SLA 快照保持不变，重复审批不重复生效 |
| F01-05 | 拒绝延期 | 拒绝原因必填，不写延期截止时间，可再次发起申请 |
| F01-06 | 完工竞争 | 完工与审批并发最多一个路径先完成，待审记录不会永久残留 |
| F01-07 | 规则冲突 | 启用规则有效期不可重叠，停用规则不阻塞新规则，重新启用时再次检查 |
| F01-08 | 历史快照 | 修改 SLA 规则不改变历史工单截止时间、预警提前量和延期许可 |
| F01-09 | 预警超期 | 各状态使用正确阶段截止时间，预警和超期日志不重复写入 |
| F01-10 | 自动关闭 | 超过评价窗口的已完成工单关闭并写系统日志，已评价工单不重复处理 |
| F01-11 | 权限隔离 | 维修人员只能申请；调度管理员只能查看授权部门申请并执行审批和规则维护 |
| F01-12 | 回归构建 | 后端测试、PC 生产构建、移动端路由和脚本静态检查全部通过 |
