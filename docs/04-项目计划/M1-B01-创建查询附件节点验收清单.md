# M1-B01 创建、查询与附件节点验收清单

## 交付范围

本节点交付工单提交、我的工单、后台工单列表、维修人员当前任务、工单详情、分类读取和附件上传下载。派单、接单、到场、处理、完工、确认、退回和评价动作不包含在本节点。

## 接口清单

| 方法 | 路径 | 权限 | 完成条件 |
|---|---|---|---|
| POST | `/workorder/orders` | `workorder:order:add` | 使用 `Idempotency-Key` 创建工单、绑定本人暂存附件、写入 `SUBMIT` 审计日志 |
| GET | `/workorder/orders/my` | `workorder:order:query` | 仅返回当前报修人的分页数据 |
| GET | `/workorder/orders/{id}` | `workorder:order:query` | 申请人、当前处理人或命中后台数据范围的用户可查看详情、附件和时间线 |
| GET | `/workorder/admin/orders` | `workorder:order:list` | 通过若依部门数据范围返回分页数据 |
| GET | `/workorder/engineer/orders` | `workorder:order:assigned:list` | 仅返回当前维修人员的当前任务 |
| GET | `/workorder/categories` | `workorder:order:add` 或 `workorder:category:list` | 返回启用中的报修分类 |
| POST | `/workorder/attachments` | `workorder:attachment:upload` | 私有路径上传、记录哈希和上传人、返回附件标识 |
| GET | `/workorder/attachments/{id}` | `workorder:attachment:download` | 先校验附件所属工单或未绑定附件上传人，再返回文件流 |
| DELETE | `/workorder/attachments/{id}` | `workorder:attachment:upload` | 仅可删除本人尚未绑定的暂存附件 |

## 数据一致性

- 创建工单、绑定附件和写入首条动作日志在同一数据库事务内完成。
- 同一用户使用同一 `Idempotency-Key` 重试时复用相同工单号；并发重复请求由工单号唯一键收敛。
- 附件上传阶段 `order_id` 为空；提交时只绑定当前用户、未绑定、`SUBMIT` 阶段且未删除的附件。
- 附件文件存放在 `workorder-private` 私有目录；响应中仅提供受鉴权下载路径，不返回对象键。
- 详情返回 `version` 和 `allowedActions`；后续状态命令必须以状态与版本条件更新。

## 验收项目

| 编号 | 检查项 | 通过标准 |
|---|---|---|
| B01-01 | 创建校验 | 分类、位置、紧急程度、影响范围和故障描述缺失时拒绝提交 |
| B01-02 | 身份快照 | 申请人 ID、姓名、电话和科室均从登录态写入，客户端字段不能覆盖 |
| B01-03 | 幂等 | 同一请求键重试只存在一张工单和一条 `SUBMIT` 日志 |
| B01-04 | 附件绑定 | 非本人、已绑定或不存在的附件 ID 使整次创建失败且不产生半绑定数据 |
| B01-05 | 行级权限 | 报修人不可查看他人工单；维修人员不可查看非当前任务；后台用户不可越过部门数据范围 |
| B01-06 | 私有附件 | 持有附件 ID 的无权用户不能读取文件；详情响应不出现 `objectKey` |
| B01-07 | 小程序提交 | 分类真实加载、失败可重试、上传失败可单项重试、提交失败保留填写内容 |
| B01-08 | 小程序查询 | 我的工单支持分页、下拉刷新、空态和失败重试；详情展示真实状态、附件和时间线 |
